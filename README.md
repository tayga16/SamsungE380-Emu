# Samsung E830 Emulator

Отдельный эмулятор Samsung SGH-E830, выделенный из переданного исходника.
Сохранено прежнее оформление настольного интерфейса: верхняя панель,
Library/Settings, Run output, LCD с масштабом до 2×, FPS и F11.
Удалены загрузчики приложений Windows CE/Windows Mobile, библиотека игр,
CAB/PE, WinCE API, игровой звук, GLES и виртуальный игровой геймпад.

## Запуск на Windows

В готовой папке сборки запустите `e830-emulator.exe`. Нажмите `Run` на карточке
Samsung SGH-E830 либо `Run Samsung E830 firmware...` и выделите одновременно
`.cla`, `.nsf` и, если есть, соответствующий `.tfs`. Настройки сохраняются рядом
с программой. NSF загружается в NOR по адресу `0x21c20000` без 20-байтового
NF4-заголовка. TFS хранится отдельно как пакет для установки; автоматической
установки его файловой системы в NAND через интерфейс пока нет.

На вкладке `Library` нажмите `Select NAND...` и выберите физический образ,
затем `Run`. Путь сохраняется в настройках и имеет приоритет над автоматическим
поиском. Отмена или неверный размер не меняют выбор. `Use automatic NAND`
сбрасывает явный выбор: программа ищет `E830XEGG1.onenand.bin` рядом с CLA,
а при отсутствии образа использует стёртую флеш-память. Исходный файл NAND
не перезаписывается; изменения гостя остаются в памяти текущего запуска.
По уточнению пользователя NAND имеет ёмкость 32 МиБ. Текущий профиль принимает
33 554 432 байта основных данных либо 34 603 008 байт с чередованием 1024 байт
данных и 32 байт spare каждой страницы. Для BML могут
понадобиться служебные данные spare. Поддержка этих форматов проверена тестами;
загрузка телефона с настоящим полным дампом пока не проверена.

Для проверенного локального образа с установленным TFS выберите
`proof/native-windows/direct-call-side/tfs-v4/full-tfs-2k.onenand.bin`.
Запуск с `E830_DSP_BOOT_HLE=1` доходит до оригинального экрана `Insert SIM / SOS`;
это диагностическая подмена части обмена DSP, а не исполнение RD16024.
В локальной папке `dist` файл `Run-E830.cmd` включает этот режим только для
запускаемого процесса и сразу запускает выбранную прошивку. Обычный `.exe`
не включает диагностический режим автоматически. По уточнению пользователя
экран `Insert SIM / SOS` считаем достигнутым экраном ожидания («меню»).
Добавлены кнопки телефона рядом с LCD: 0–9, */#, стрелки, OK,
софт-клавиши и Call/End. Управление мышью либо с клавиатуры ПК:
стрелки, Enter (OK), F1/F2 (софт-клавиши), F3/F4 (Call/End), F5/F6 (*/#),
цифры 0–9. При потере фокуса или уходе с Run output нажатия отпускаются.
Подтверждено на оригинальной прошивке: «1» открывает экран набора номера.
OK и левая софт-клавиша распознаются, но без SIM список приложений не открыли.
Для новой локальной сборки с кнопками используйте **`dist/Run-E830-Keypad.cmd`**:
она запускает обновлённый `e830-emulator.exe` с DSP boot HLE и **без SIM**.
Открытое старое окно не обновляется автоматически. NAND и прошивка
используются из прежних настроек.
Актуальная GUI-сборка в `dist/e830-emulator.exe` содержит кнопки и новый HLE.
Запускатели разделены явно:

- `Run-E830-NoSIM.cmd` (или `Run-E830-Keypad.cmd`) — проверенный запуск без
  карты с DSP boot HLE; RF/батарея HLE отключены. Доходит до `Insert SIM / SOS`
  с выбранным установленным TFS NAND; список приложений пока не подтверждён.
- `Run-E830-HLE.cmd` — экспериментальная SIM вместе с RF «эфир без сети» и
  батареей HLE. Штатная анимация продвигается, но меню с SIM пока не достигнуто.
- `Run-E830.cmd` сохраняет прежний выбор запуска с SIM и вызывает HLE-запускатель.
- `Run-E830-RF-Tagged033f-Wrap.cmd` — новый отдельный RF-кандидат, проходит
  прежнюю остановку443,8млн. При открытии списка приложений остаётся RF-ошибка;
  старые запускатели эту правку не включают.

Режим и предупреждение отображаются в Library и Run output, вне LCD телефона.
Обычный `.exe` не включает SIM/HLE автоматически; переменные запускателей
действуют только внутри запуска. Старое открытое окно нужно закрыть вручную
и запустить новый файл, иначе оно продолжит работать на прежней сборке.

В текущем исходном коде виртуальная тестовая SIM уже отвечает на SELECT,
GET RESPONSE, STATUS и READ BINARY; прошивка читает язык, IMSI, ICCID и
несколько служебных файлов через свой DMA-драйвер. Это пока **экспериментальная
версия, не исправление SIM**: после чтения карты прошивка останавливается
с `EA020101`, ожидая отсутствующий результат DSP/радиочасти. Меню с SIM не
подтверждено. Основной `.exe` в `dist` обновлён; старый
`e830-emulator-keypad.exe` оставлен для совместимости, но keypad-запускатель
теперь использует основной обновлённый файл без SIM. Фиктивные данные тестовой
карты не предоставляют подключение к сети или настоящую подписку. Подробности
и воспроизводимая проверка — в [журнале исследования](docs/boot-investigation.md).

Для исследования HLE в текущем исходном коде доступны отдельно включаемые
`E830_DSP_RF_HLE=empty` и `E830_ANALOG_HLE=battery` вместе с
`E830_DSP_BOOT_HLE=1` и `E830_SIM_PRESENT=1`. Это искусственные условия
«эфир без сети» и измерение питания примерно 3,7 В, а не полноценная эмуляция
DSP/АЦП. Прошивка проходит первую RF-проверку и `70012904`. Расписание RF
теперь учитывает фазу гостевого таймера и конвейер следующего кадра по
допущению HLE. Очистка расписания не отменяет уже принятые измерения;
нулевая маска не запускает старые команды заново. Профиль `0333` поддержан
после проверки штатной поправки −139. Также проверен оригинальный ARM-код:
он записывает 8 байт команды, но копирует 40 байт повторно используемого
буфера. Остаток предыдущей принятой команды распознаётся только при точном
совпадении с проверенной историей, в том числе для полного пакета из трёх
измерений в конце сканирования. Поддержаны проверенные профили `033f`
с поправками −160/−163 и `033d` с поправкой −159, повторный запуск сканирования
с `033d`/`033f` и наблюдаемые переходы из `0333`/`033d`/`033f` в `033f`. Остаток буфера
должен точно совпадать с последней принятой командой. Пройдены прежние
остановки на 302,0, 304,8, 321,2, 329,4 и 345,9 млн инструкций.
Также исправлен пропуск событий RF/таймера при ускоренной очистке памяти:
пока RF-запросы выполняются, исходные циклы исполняются без перемотки.
Пройдены остановки на 356,4 и 394,5 млн. По трассе оригинального ARM
добавлен профиль `0333` с флагом диапазона и строгая проверка перехода
буфера из `885/033f` в `512..516/0333`; синтетический уровень −400 не менялся.
Новая правка проходит `EA020101` на 410,8 и 427,3 млн: поддержаны `033d`/`033f`
с флагом диапазона, точная история четырёх запросов `807..810/0333` и
`807..810/033d`, а также захваченные переходы между этими профилями.
Теперь исправлены точный хвост `807..810/033f` и переход `810 → 512..516/033f`:
остановка на 443,8 млн пройдена, контроль дошёл до 900 млн без ошибки памяти.
Экспериментальная GUI-сборка запускается через `dist/Run-E830-RF-Tagged033f-Wrap.cmd`
(`e830-emulator-rf-tagged033f-wrap.exe`); прежние кандидаты, основной
`dist/e830-emulator.exe` и старые запускатели сохранены и этой правки не содержат.
Анимация продвинулась ещё на несколько кадров, но внизу появились
графические артефакты. Новый LCD изменился; распознавание текста читает `Menu`
и `Contacts`. После левой экранной кнопки OCR читает `Messages / Select / Back`,
но затем снова возникает отсутствующий RF-результат и `READ_UNMAPPED`.
Стабильная навигация и визуальная проверка ещё не выполнены. По умолчанию эти режимы
выключены; обновлённый GUI использует их только через явный HLE-запускатель
или соответствующие переменные окружения.

Оптимизирован обработчик инструкций: убраны постоянные диагностические чтения
памяти и повторные проверки прерываний. На этом ПК контрольный CLI-запуск
до 600 миллионов инструкций сократился с 237 до 74 секунд; повторный замер —
с 298 до 122 секунд (ускорение примерно в 2,5–3,2 раза, зависит от нагрузки ПК).
Финальная сборка с объединённой проверкой адресов циклов прошла тот же запуск
за 96 секунд. Отдельный выигрыш этой дополнительной правки пока не выделен.
Состояние CPU, число IRQ, системный таймер и итоговый экран совпали с исходной
версией. Это замер CLI, а не обещание точного времени загрузки в GUI.
Частота гостевых таймеров и прошивка не изменены; подробности — в
[журнале исследования](docs/boot-investigation.md).

В локальном комплекте теперь создан `firmware/E830XEGG1.onenand.bin`:
32 МиБ основных данных и 1 МиБ spare, всего 34 603 008 байт. Образ заполнен
`0xFF`, как стёртая микросхема, и автоматически подхватывается старым интерфейсом.
Он ещё не отформатирован и не содержит установленной файловой системы.
2099 файлов и 127 каталогов из CFG/TFS извлечены в
`firmware/E830XEGG1.tfs-staging/files`; их размеры, смещения и SHA-256 записаны
в `manifest.json` рядом. Это исходные ресурсы для последующей установки в NAND.

Для создания нового стёртого образа и подготовки ресурсов:

```powershell
python .\tools\prepare_nand.py --output .\firmware\new.onenand.bin --cfg .\firmware\E830XEGG1.cfg --tfs .\firmware\E830XEGG1.tfs --stage .\firmware\new.tfs-staging
```

Скрипт проверяет внешний CFG и точный размер TFS до записи результатов;
существующие образы и каталоги он не перезаписывает. Форматирование BML/STL/KFATFS
и установка ресурсов этим подготовительным скриптом не выполняются.

## Проверка полной установки TFS — 25.10.2026

В отдельной локальной проверке оригинальные функции Samsung установили
**2099 файлов, 127 каталогов и 26 268 942 байта** в новый тестовый NAND.
После перезапуска все файлы прочитаны целиком и совпали с исходниками.
Для размещения пакета штатному форматировщику задан кластер 2 КиБ:
при его исходном выборе 4 КиБ пакет не помещался в логический том 32-МиБ NAND.

Образ находится в
`proof/native-windows/direct-call-side/tfs-v4/full-tfs-2k.onenand.bin`.
Подробности, команды повторения и ограничения:
[README проверки](proof/native-windows/direct-call-side/tfs-v4/README.md).
Это локальные исследовательские результаты под исключённым `proof`.
Общий код и старый интерфейс не изменены; прежний образ в `firmware` сохранён.

С новым образом запуск прошивки E830 на 120 миллионов инструкций
показал прежнюю заставку Samsung без ошибки доступа к памяти. Дополнительная
трассировка подтвердила успешные BML_Open, инициализацию файлового слоя и mount
в самой прошивке E830. Меню пока не достигнуто; следующий этап — исследовать
ожидание после заставки. SHA-256 образа:
`d305c8e0b27e86ecec70534be1ee2c917c1556e675d5868573e600b7cf341a56`.

## Сборка на этом ПК

```powershell
powershell -ExecutionPolicy Bypass -File .\bootstrap-windows.ps1
powershell -ExecutionPolicy Bypass -File .\build-windows.ps1
powershell -ExecutionPolicy Bypass -File .\build-windows.ps1 -Test
```

Инструменты находятся локально в `.tools`; сборка выполняется нативно на
Windows x64. Скрипты используют установленные на этом ПК Git, 7-Zip и Python
3.12. Для служебной символической ссылки при сборке Unicorn могут требоваться
права администратора либо Windows Developer Mode.

## Диагностика прошивки

```powershell
.\target\release\e830-cli.exe .\firmware\E830XEGG1.cla ".\firmware\E830 eeprom.nsf" --tfs .\firmware\E830XEGG1.tfs --max-instructions 1200000000 --dump-lcd-frame .\e830-lcd.ppm
```

Доступны `--trace-mmio`, `--peek 0x...`, `--break-at`, `--break-after`,
`--dump-ram`, `--dump-uart` и `--onenand-image путь_к_дампу`.
`--tfs-source` задаёт отдельный диагностический источник в окне `0x1c000000`.
`E830_WATCH_PC` принимает адреса через запятую и записывает регистры в этих
точках; `E830_WATCH_LIMIT` ограничивает число записей. Есть также `E830_PC_LOG`
и `E830_TRACE_IRQEN`. Принудительные IRQ, подстановка состояния RTOS и прямое
ускорение его часов удалены.

Для зависания в экспериментальном SIM/RF HLE добавлен офлайн-разборщик
`tools/inspect_rf_memory_trace.py`: он восстанавливает записи в shared RAM
DSP именно на момент отправки команды, показывает активные каналы, флаг
диапазона, остаток буфера и чтения флагов результата. Неизвестные байты не
считает нулями и память эмулятора не меняет. Ограниченная трасса выявила
неподдержанный `band tag` у запросов512..521/0333 перед `EA020101`.
После проверки исходной арифметики этот этап исправлен в отдельной RF Debug
сборке; tagged033d и точная история `807..810/0333` также исправлены.
Следующая трасса выявила tagged033f после хвоста `807..810/033d`.
Меню с SIM пока не достигнуто.
Команды повторения и проверка независимыми снимками:
[отладка RF-памяти](docs/rf-memory-debugging.md).

## Состояние

Текущая нативная сборка показывает настоящую заставку Samsung. Исправлены
проверка TCM, UART, обмен I2C с обработкой отсутствующих устройств и доступ
к shared RAM DSP. Прошивка сама инициализирует стек RTOS и разрешает IRQ.
Добавлены NOR и предварительная модель OneNAND с выбором секторов.

Экран ожидания **Insert SIM / SOS достигнут** с проверенным NAND и
`E830_DSP_BOOT_HLE=1`; открытие списка приложений пока не проверено.
При запуске со стёртым NAND прошивка останавливается
на ошибке `0x18000002`: нижележащий BML возвращает `0x800b0000` и сообщает,
что NAND не отформатирована. С проверенным полным TFS этот этап проходит успешно;
остаётся дальнейшая проверка ожидания, таймеров и периферии. DSP не исполняется,
радиочасть не реализована. Кнопки уже проходят через оригинальный драйвер;
экран набора номера подтверждён, навигация в список приложений — нет.
Доказательства и актуальные адреса:
`docs/boot-investigation.md`.

Старые заметки QEMU сохранены в `docs/boot-investigation-legacy.md`. Они не
описывают текущую нативную модель. Сборка выполняется непосредственно в Windows.

Прошивка в `firmware` — частные локальные входные данные. Она не входит в
лицензию исходного кода. Лицензия производного исходного кода: Apache-2.0/MIT;
см. LICENSE и NOTICE.
