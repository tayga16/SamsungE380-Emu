# Decompilation notesThis directory contains small, reviewable descriptions produced during theE830 investigation.  They are not firmware exports and are not intended toreconstruct or redistribute Samsung binaries.Included material may contain:- manually written pseudocode for a path that was verified by traces;- curated addresses and descriptive labels used by the emulator investigation;- instructions for reproducing local analysis with a user-supplied image.Raw CLA/TFS/NSF images, complete DEF/MAP files, IDA/Ghidra databases, generatedassembly listings and RAM/NAND captures must remain outside Git.  The repositorytools accept those files locally without copying their contents into the tree.## Current slice[`hkbd-menu-input.md`](hkbd-menu-input.md) records the late-menu keypad path.It narrows the inert-arrow problem to code after the common HKBD queue function;the passive diagnostic now follows the keyboard profile requests, HKBDconfiguration, release gate, EDP forwarding, MMI filter and UI command path. Thecurrent static lead is a stale slot-20 value for the Up record, but the runtimeproof is still pending.[`e830-hkbd-symbols.csv`](e830-hkbd-symbols.csv) is a compact set of labels forthat slice.  Labels ending in `_site` identify an observed instruction or callsite rather than a proven function entry.The local D500 MAP supplied during the follow-up was used only as a naming aidfor shared Samsung modules.  No D500 address is treated as an E830 address, andthe complete MAP remains outside the repository.## Local symbol extraction`tools/extract_def_symbols.py` reads a local Samsung DEF file and prints onlymatching address symbols.  For example:```powershellpython .\tools\extract_def_symbols.py .\firmware\E830XEGG1.def `  --prefix a_hkbd_ --format csv```The input file is never modified.  Redirect output only when the selectedsymbols are safe and useful to publish.
